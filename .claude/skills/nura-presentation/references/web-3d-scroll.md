# Интерактивные web-презентации: 3D, скролл-режиссура, анимация

Техническое руководство для «эффектного» формата: страница, где по скроллу
камера ведёт зрителя вокруг и внутрь 3D-объекта (подстанция, ЛЭП, СЭС,
BESS), а подписи и секции объясняют происходящее.

## Стек

- **Three.js** (cdnjs) — 3D-сцена. Подключать с одобренного CDN
  (cdnjs.cloudflare.com), версию фиксировать.
- **GSAP + ScrollTrigger** (cdnjs) — скролл-анимация и таймлайны. Либо
  собственный rAF-движок на `IntersectionObserver` + lerp, если GSAP
  избыточен.
- Всё остальное — ванильные HTML/CSS/JS в одном файле артефакта
  (или несколько файлов через `files` при больших объёмах).
- Публикация — приватный Artifact; перед версткой обязательно загрузить
  скилл `artifact-design`, для графиков — `dataviz`.

## Восстановление 3D-объекта по чертежам

1. Прочитай чертёж/компоновку (PDF — через чтение страниц как изображений).
   Выпиши: габариты площадки, список и расстановку оборудования, высоты.
2. Строй геометрию из примитивов Three.js (Box, Cylinder, Lathe, Extrude)
   со **соблюдением реальных пропорций и взаимного расположения** —
   узнаваемость компоновки важнее детализации болтов.
3. Типовые элементы и их читаемые образы:
   - силовой трансформатор: бак + радиаторы (ряды пластин) + вводы
     (конусы-изоляторы) + консерватор (горизонтальный цилиндр);
   - порталы ОРУ: П-образные рамы, гирлянды изоляторов (стопки дисков),
     ошиновка — провисшие цепные линии (catenary) или жёсткие трубы;
   - выключатели, разъединители, ТТ/ТН: колонны изоляторов (ребристые
     цилиндры — LatheGeometry) на рамах;
   - КРУЭ/ЗРУ/ОПУ: здания с характерной компоновкой;
   - опоры ЛЭП: решётчатые фермы (повторяющиеся сегменты), провода —
     catenary между точками подвеса;
   - СЭС: столы ФЭМ рядами (InstancedMesh — тысячи панелей без потери FPS),
     инверторные станции, трансформаторные пункты;
   - BESS: контейнеры рядами, ПКС/инверторы, трансформатор.
4. Материалы: PBR (MeshStandardMaterial), сдержанные цвета из палитры
   (графит, сталь, керамика изоляторов; токоведущие части можно подсвечивать
   `--nura-volt` в момент объяснения). Среда — нейтральный тёмный фон
   или лёгкий градиент, «земля» — тёмная плоскость с тонкой сеткой.
5. Свет: key + fill + rim, мягкие тени (PCFSoft). Без кислотных бликов.

## Скролл-режиссура

Принцип: **скролл — это таймлайн фильма**. Страница состоит из секций;
прогресс скролла (0→1) управляет камерой, разрезами и подписями.

- Канва с 3D — `position: fixed` на весь экран; поверх скроллятся секции
  с текстом (прозрачные спейсеры задают длительность «сцен»).
- Камера движется по ключевым точкам (позиция + цель взгляда на каждую
  сцену); интерполяция плавная (lerp/ease), без рывков.
- Типовая драматургия облёта:
  1. общий план объекта (установить масштаб — силуэт человека или машины
     для сравнения);
  2. облёт по дуге с остановками у ключевых узлов;
  3. **показ «что внутри»**: разрез или послойная разборка;
  4. схема/цифры;
  5. возврат к общему плану — финальный кадр.
- Подписи-выноски: появляются синхронно с приближением камеры к узлу
  (fade+rise), исчезают при уходе. Линия-выноска проецируется из 3D-точки
  в экранные координаты (`Vector3.project(camera)`).

## «Что внутри»: разрезы и разборка

- **Разрез**: `clippingPlanes` в Three.js — плоскость сечения анимируется
  по скроллу, объект «вскрывается» (например, бак трансформатора → активная
  часть: магнитопровод + обмотки). Кромку среза подсветить акцентом.
- **Взрыв-схема**: каждому узлу задать вектор разлёта; параметр 0→1
  разводит узлы из собранного положения; подписи появляются у разлетевшихся
  частей. Хорошо для состава поставки.
- **Послойное появление (этапы строительства)**: группы по этапам
  (фундаменты → металлоконструкции → оборудование → ошиновка) появляются
  последовательно (scale/fade) — наглядная этапность СМР.

## Однолинейные схемы и перетоки

- Схема — SVG в фирменном стиле (линии 1.5–2px, шрифт IBM Plex Mono,
  стандартные обозначения элементов).
- Переток мощности: анимация `stroke-dashoffset` (бегущий пунктир) вдоль
  линий; направление и интенсивность читаемы. Активный участок —
  `--nura-volt`, остальное приглушено.
- Синхронизация с рассказом: по мере скролла подсвечиваются участки схемы,
  о которых идёт речь; можно связать со сценой 3D (камера у трансформатора —
  на схеме подсвечен трансформатор).

## Фото, видео, внешние рендеры (Higgsfield и др.)

- Пользовательские фото/видео/рендеры загружай в asset-хранилище артефакта
  (publish с `asset: true`) и встраивай по полученным URL.
- Полноэкранные видео-секции: `muted autoplay loop playsinline`,
  постер-кадр, деградация в статичное изображение при ошибке загрузки.
- Переходы 3D ↔ видео/фото: затемнение или совпадение ракурса (камера 3D
  подводится к ракурсу съёмки — монтажная склейка).

## Производительность и надёжность

- Бюджет: страница ≤ 16 МБ; сцена — десятки тысяч полигонов, не миллионы;
  повторяющиеся элементы — InstancedMesh; `renderer.setPixelRatio(
  Math.min(devicePixelRatio, 2))`.
- Рендер по требованию: перерисовывать только при изменении прогресса
  скролла/resize, не жечь батарею в простое.
- Фолбэк без WebGL: проверка поддержки; при отсутствии — статичные рендеры
  (заранее отснятые кадры сцены) с теми же подписями.
- Телефон: презентацию часто откроют с телефона по ссылке — проверять
  вёрстку на ширине ~390px, тач-скролл, вес страницы.
- `prefers-reduced-motion: reduce` — отключать агрессивные анимации,
  оставлять статичные кадры сцен.
- Текст страницы должен существовать и без 3D (доступность + надёжность):
  3D усиливает рассказ, но не является его единственным носителем.

## Чек-лист перед сдачей web-версии

1. Скролл от начала до конца: нет рывков камеры, «мёртвых» пустых зон,
   наложений текста.
2. Все подписи появляются у правильных узлов и вовремя исчезают.
3. FPS стабильный на ноутбуке средней мощности (эмулировать троттлинг).
4. Открытие на ширине телефона: читаемость, отсутствие горизонтального
   скролла.
5. Фолбэк и постеры работают (отключить WebGL/сеть и проверить).
6. Орфография всех подписей и единицы измерения.
